# Изменения

## 0.8.0

- Зависимость обновлена до go-cms-kernel v0.14.0. Успешный публичный JSON-ответ ресурса содержит `resource.breadcrumbs` с заголовками и адресами опубликованных предков и текущего ресурса.
- Профиль Starter не добавляет главную страницу в начало цепочки отдельно; настройка `IncludeHomeInBreadcrumbs` доступна проектным профилям. Совместимая админка v0.8.1 синхронизирована без изменений интерфейса.

## 0.7.1

- Зависимость обновлена до go-cms-kernel v0.13.1: ресурсы с устаревшим выбором полей виджета остаются доступны в дереве и редакторе для исправления. Совместимая админка v0.8.0 не менялась.

## 0.7.0

- Зависимость обновлена до опубликованного go-cms-kernel v0.13.0 с виджетом `core_resource_fields`: редактор выбирает поля текущего шаблона, публичный ответ содержит их исходные значения в `data.fields`.
- Совместимая админка v0.8.0 добавляет выбор полей шаблона и исправляет сохранение виджета при открытом списке выбора.

## 0.6.0

- Зависимость обновлена до опубликованного go-cms-kernel v0.12.0.
- CLI Core для создания пользователя теперь принимает `--password` либо `--generate-password`; смена пароля принимает `--password` напрямую вместо чтения пароля из stdin.

## 0.5.1

- Конфигурация Redis для счётчика просмотров использует общий клиентский контракт go-cms-kernel v0.10.0. Backend проекта больше не импортирует `go-redis/v9` напрямую; Redis-кэш и накопитель просмотров остаются раздельными.
- Совместимая админка v0.6.1 синхронизирована с новым комплектом, без изменений интерфейса.

## 0.5.0

- Добавлен отдельный Redis-накопитель просмотров ресурсов с записью пакетов в PostgreSQL каждые 45 секунд; отказ Redis не останавливает backend.
- Профиль Core выбирает накопитель отдельно от обычного кэша. Для запуска нескольких экземпляров используется общий Redis и общий PostgreSQL.
- Зависимость обновлена до опубликованного go-cms-kernel v0.9.0; в редакторах совместимой админки v0.6.0 виден сохранённый итог просмотров.

## 0.4.0

- Зависимость kernel обновлена до опубликованного v0.8.0; обычные Go- и Docker-сборки используют модуль без локальных подмен.
- Starter использует `[]kernel.Module`, `core.New(core.Config{...})` и `admin.New()`. Параметры модулей проверяются компилятором по типам; ошибки значений, bindings и зависимостей останавливают запуск до HTTP, включая профили без сайтов.
- Профиль Starter вынесен в отдельный пакет; обновлены справочник шести модулей и примеры создания профилей.
- Публичные API доступны под `/api`; адреса страниц, файлов `/_cms/files/...` и `/healthz` сохранены.
- Ресурсы читаются через `GET/HEAD /api/resources/resolve` и `/api/resources/resolve/{path}`. Ресурсный обработчик больше не является fallback для неизвестных URL; неизвестные маршруты возвращают 404, прочие методы resolver — 405 с `Allow: GET, HEAD`. `ResourceLink` перенаправляет на новый API-адрес, а пути страниц, меню, поиска и SEO не меняются.


- Документирован новый контракт типизированных валидаторов kernel для профилей, Forms и Mail. Опции `MinItems`, `MaxItems` и `Pattern` заменены конфигурируемыми проверками; старые данные разработки нужно пересоздать перед запуском новой версии.

## 0.3.0

- Зависимость kernel обновлена до v0.3.0.
- Пакетная авторизация: один SQL-запрос для набора разрешений; обновлены сессия админки и наборы возможностей.
- Страницы LibraryItem получают версии вместе с основными строками: на один запрос меньше без изменения сортировки и курсоров.
- Dashboard загружает независимую статистику параллельно, сохраняя зависимость «сайты → ресурсы» и отмену при ошибке.
- Изменились Go-контракты `security.Authorizer` и access-репозитория; собственные реализации нужно обновить. HTTP-ответы и правила доступа сохранены.

## 0.2.0

- Ядро 0.2.0: защита от устаревших runtime между репликами, отзыв сессий, исправление гонок кэша и ограничения дорогих операций.
- Kafka в стандартном Compose и starter вместо отбрасывания событий. Redis ограничен 256 MiB.
- Dev-seed выключен по умолчанию. Добавлена команда bootstrap-admin; make env генерирует уникальные секреты.
- JWT сессии хранятся в PostgreSQL, срок по умолчанию — 30 минут.
- Независимая админка 0.2.0 поддерживает плагины и явные overrides через публичный API.

Схема pre-production исправлена напрямую: существующую базу разработки нужно пересоздать перед запуском версии. Старые JWT больше не действуют. Команды удаления пользовательских volumes автоматически не выполняются.
