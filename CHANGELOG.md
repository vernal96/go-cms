# Изменения

## В разработке

- Документирован новый контракт типизированных валидаторов kernel для профилей, Forms и Mail. Опции `MinItems`, `MaxItems` и `Pattern` заменены конфигурируемыми проверками; старые данные разработки нужно пересоздать после публикации согласованной версии kernel. В `backend/go.mod` пока остаётся `v0.3.0`; локальная совместимость проверяется временным Go workspace.

## 0.3.0

- Зависимость kernel обновлена до v0.3.0.
- Пакетная авторизация: один SQL-запрос для набора разрешений; обновлены сессия админки и наборы возможностей.
- Страницы LibraryItem получают версии вместе с основными строками: на один запрос меньше без изменения сортировки и курсоров.
- Dashboard загружает независимую статистику параллельно, сохраняя зависимость «сайты → ресурсы» и отмену при ошибке.
- Изменились Go-контракты `security.Authorizer` и access-репозитория; собственные реализации нужно обновить. HTTP-ответы и правила доступа сохранены.

## 0.2.0

- Ядро 0.2.0: защита от устаревших runtime между репликами, отзыв сессий, исправление гонок кэша и ограничения дорогих операций.
- Kafka в стандартном Compose и starter вместо отбрасывания событий. Redis ограничен 256 MiB.
- Dev-seed выключен по умолчанию. Добавлена команда bootstrap-admin; make env генерирует уникальные секреты.
- JWT сессии хранятся в PostgreSQL, срок по умолчанию — 30 минут.
- Независимая админка 0.2.0 поддерживает плагины и явные overrides через публичный API.

Схема pre-production исправлена напрямую: существующую базу разработки нужно пересоздать перед запуском версии. Старые JWT больше не действуют. Команды удаления пользовательских volumes автоматически не выполняются.
