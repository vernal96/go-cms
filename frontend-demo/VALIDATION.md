# Проверки API меню и демосайта

Проверено 15 сентября 2026 года.

## Выполнено успешно

- `go test ./...`, `go vet ./...`, `go build ./...` из `backend`.
- `go test -race ./kernel/modules/core ./kernel/modules/core/resource`:
  дерево, ссылки, сроки публикации, параметры, проверки доступа перед кешем,
  попадание без повторной загрузки, изоляция сайтов, ошибки/повреждение кеша,
  дедлайн, запрет кеширования ошибок, параллельное наполнение и изменение,
  инвалидация после восстановления ревизии.
- Тесты демосервера в Node.js 24: 7 проверок, без пропусков.
- `scripts/check-menu.mjs` на реальном backend с PostgreSQL и Redis:
  корень, глубина, скрытые контейнеры, ссылки, изменение адреса цели,
  показ/скрытие, публикация и снятие с публикации по времени,
  перемещение, порядок, восстановление ревизии, удаление/восстановление,
  изоляция сайтов и сброс кеша обоих сайтов при переносе ресурса.
  Временные сайты удалены после проверки.
- Повторный публичный запрос использует ту же запись Redis: содержимое записи
  сохраняется, её TTL уменьшается и не продлевается повторной записью.
- `make demo-start`: повторное наполнение не создаёт дубли, сохраняет контент,
  существующие ID меню и запускает здоровый контейнер демо.
- Chromium: все 12 страниц на ширинах 1440 и 390 px без горизонтального
  переполнения; основное меню, меню проектов и оба футера присутствуют.
- Редактирование подписи ссылки футера через настоящую админку:
  сохранение → обновление страницы демо → новая подпись из CMS.
  Тестовая подпись восстановлена, восстановление проверено в браузере.
- Конфигурация Docker Compose и `git diff --check`.

## Найдено и исправлено

Восстановление ревизии обычного ресурса не инвалидировало кеш после записи.
Добавлена инвалидация общего тега ресурсов сайта и регрессионный тест;
живая проверка восстановления ревизии проходит.

## Границы проверки

Общий запуск Go-тестов пропускает внешние интеграционные тесты, требующие
неустановленных `CMS_TEST_*` переменных. Например,
`TestPostgresMigrationsAndSiteRepository` требует `CMS_TEST_POSTGRES_HOST`.
Их пропуск не считается успешным интеграционным тестированием; новое меню
отдельно проверено через живой HTTP API с действующими PostgreSQL и Redis.

Недоступность хранилища кеша проверена подменой Store в модульных тестах.
Работающий общий Redis намеренно не останавливался.
