# Демосайт «Контур»

Рабочий сайт архитектурной студии на GO CMS: 12 ресурсов с русским контентом,
три проекта, три статьи, услуги, о студии и контакты. Есть поиск по реальному
индексу CMS, переходы между страницами, раскрывающиеся ответы на вопросы,
адаптивная версия и страница 404. Все проекты и контакты вымышлены;
форма заявки и отправка писем в это демо не входят.

## Открыть сейчас

- Сайт: [http://localhost:4173](http://localhost:4173).
- Админка: [http://localhost:5173](http://localhost:5173).
- Логин: `admin`, пароль: `admin-dev-only-2026`.

В админке выберите сайт **demo.localhost**. Его ID зависит от базы данных.
`demo.localhost` — домен сайта в CMS; браузеру достаточно адреса `localhost:4173`.
Запись в hosts и настройка DNS не нужны: сервер демо сам передаёт CMS нужный Host.

## Запуск с нуля

Нужны Docker Engine / Docker Desktop с запущенным Docker daemon, Docker Compose
с поддержкой `--wait`, GNU Make и свободные порты из корневого `compose.yaml`.
Node.js и Go на компьютере не нужны: приложения работают в контейнерах.
В Windows команды выполняются в WSL с включённой интеграцией Docker Desktop.

Из корня репозитория:

```bash
cd /home/denis/projects/cms
make demo
```

Команда собирает и запускает CMS, применяет миграции и стандартные dev seeds,
добавляет гостевые права чтения, создаёт демосайт через административный HTTP API
и запускает его frontend. После успешного завершения откройте
[http://localhost:4173](http://localhost:4173) в обычном браузере.

**Если CMS уже запущена**, достаточно:

```bash
make demo-start
```

Повторный `make demo-start` сохраняет существующий контент. Создаются только
недостающие ресурсы; пустые ресурсы после прерванного наполнения заполняются.
Существующие сайты не переименовываются и не удаляются.
`make demo` также выполняет стандартную процедуру `make up` со штатными dev seeds.

Гостевые разрешения `core.site.read` и `core.resource.read` в текущей CMS общие:
они разрешают посетителям читать опубликованный контент публичных сайтов.
Приватные сайты и закрытые ресурсы продолжают проверяться backend.

## Изменить контент и увидеть результат

1. Откройте админку, войдите и выберите **demo.localhost**.
2. В дереве ресурсов откройте страницу, например **О студии**.
3. Редактируйте HTML в поле **Контент**. Для сохранения оформления меняйте текст
   внутри существующих блоков; для структурных изменений используйте редактор исходного HTML.
4. Нажмите **Сохранить**.
5. Обновите [страницу студии](http://localhost:4173/about).
   Пересборка и перезапуск frontend не нужны: он читает CMS при каждом запросе.

Системный **Заголовок** определяет заголовок вкладки браузера; **Аннотация** —
meta description и описание в поиске. Видимый заголовок и блоки страницы находятся
в **Контенте**. Поля шаблона `page_title` и `page_text` заполнены как демонстрационные
данные; данный frontend не выводит их отдельно. Произвольные виджеты и формы
в этом frontend не реализованы. Меню загружаются из публичного API CMS.

Можно создавать дополнительные опубликованные ресурсы типа «Страница» с контентом
`html`: они открываются по своему пути на `localhost:4173`. Чтобы добавить их в
навигацию, разместите ресурс на нужном уровне дерева и включите показ в меню.

## Меню и быстрый кеш

Основное меню запрашивается через `GET /menu?depth=1`. Оно содержит опубликованные
ресурсы с `parent_id = null`, включая главную. Разделы демо находятся на этом же
уровне; проекты и статьи остаются внутри своих разделов.

На страницах проектов дополнительно запрашивается `/menu?parent_id=<ID проектов>`.
Два футера получают меню по ID скрытых ресурсов «Футер 1» и «Футер 2».
Их дочерние ресурсы-ссылки указывают на реальные разделы сайта.
ID сохраняются наполнением в `/data/menu-config.json` общего volume `demo_data`;
их также печатает `make demo-start`. Не нужно прописывать ID в коде frontend.

- Без параметров `/menu` возвращает всё подходящее дерево без ограничения глубины.
- `parent_id` выбирает потомков указанного ресурса; сам родитель не возвращается.
- Скрытый пункт исключается вместе со своей веткой. Флаг скрытия игнорируется
  только у явно выбранного начального родителя.
- `depth=1` возвращает первый уровень результата, `depth=2` — два уровня.
- Порядок задаётся сортировкой дерева. Подпись — «Пункт меню», а при пустом поле — заголовок.
- Ссылки возвращают адрес назначения. Недоступные цели и циклы ссылок исключаются.
- Публичность и сроки публикации проверяются и для начального родителя.

Готовое меню кешируется backend через `core.hot` (в dev — Redis), отдельно для
каждой комбинации сайта, родителя и глубины. Максимальный TTL — 5 минут;
настройка Go: `core.Config.MenuCacheTTL`. Срок сокращается до ближайшего изменения
публикации. Изменение ресурсов автоматически сбрасывает меню сайта, включая
изменение цели ссылки из другого раздела. Перенос между сайтами сбрасывает оба
сайта. При недоступности кеша backend читает БД и регистрирует ошибку кеша.

После сохранения изменений в админке достаточно обновить страницу браузера.
Frontend не кеширует HTML и запрашивает меню анонимно при формировании страницы.

### Postman

Импортируйте `menu.postman_collection.json`. В переменных коллекции задайте
`base_url`, `domain` и актуальные ID из вывода наполнения. Значения по умолчанию
соответствуют текущему локальному демо; при создании сайта заново ID изменятся.
Используйте backend на порту 8080 и заголовок `Host: demo.localhost`.
Порт 4173 возвращает готовый HTML сайта.

Пример:

```bash
curl -H 'Host: demo.localhost' -H 'Accept: application/json' \
  'http://localhost:8080/menu?depth=1'
```

Живая проверка API создаёт временный отдельный сайт и удаляет его после теста:

```bash
docker compose --profile demo run --rm --no-deps demo node scripts/check-menu.mjs
```

## Перезапуск и остановка

```bash
# Запустить уже созданные контейнеры после остановки
# (без повторного наполнения)
docker compose --profile demo up -d --wait

# Состояние сайта
docker compose --profile demo ps demo

# Логи
docker compose --profile demo logs --tail=100 demo

# Остановить только публичный frontend
docker compose --profile demo stop demo

# Остановить всё; данные остаются в volumes
docker compose --profile demo down
```

После изменения кода frontend: `make demo-start`. Эта команда пересобирает образ.
Не удаляйте Docker volumes, если хотите сохранить изменения в админке.

## Порт и параметры

В корневой `.env` можно добавить:

```dotenv
DEMO_PORT=4173
DEMO_DOMAIN=demo.localhost
```

Например, `DEMO_PORT=4174` переносит сайт на `http://localhost:4174`.
После изменения выполните `make demo-start`. Backend остаётся доступным frontend
в сети Docker как `http://server:8080`, независимо от его внешнего порта.

Если пароль администратора изменён, наполните сайт отдельно с вашими данными:

```bash
read -r -p 'Логин администратора: ' DEMO_ADMIN_LOGIN
read -r -s -p 'Пароль: ' DEMO_ADMIN_PASSWORD
export DEMO_ADMIN_LOGIN DEMO_ADMIN_PASSWORD
docker compose --profile demo build demo
docker compose --profile demo run --rm --no-deps \
  -e DEMO_ADMIN_LOGIN -e DEMO_ADMIN_PASSWORD demo node scripts/seed.mjs
unset DEMO_ADMIN_LOGIN DEMO_ADMIN_PASSWORD
docker compose --profile demo up -d --wait demo
```

Гостевые права должны быть уже выданы командой `make demo-start` либо штатными
командами console из её рецепта в Makefile.

## Если страница не открывается

- Убедитесь, что Docker запущен, затем выполните `make demo-start`.
- При занятом порте измените `DEMO_PORT`.
- **502**: проверьте `docker compose ps server` и логи сервера.
- **403**: проверьте публикацию сайта и гостевые права чтения.
- **404**: проверьте наличие и публикацию ресурса; домен в админке должен
  совпадать с `DEMO_DOMAIN`.
- В Windows открывайте `localhost:4173`, а не адрес Docker-контейнера.

## Устройство

`frontend-demo` — отдельное приложение на Node.js 24 без npm-зависимостей.
`server.mjs` читает публичный JSON CMS и собирает HTML. Он не использует
административную авторизацию и не проксирует management API. HTML создаётся
доверенными редакторами CMS; выполнение скриптов запрещено CSP.

`public/` содержит стили и локальные SVG-иллюстрации. Внешние шрифты, изображения
и CDN не требуются. `scripts/content.mjs` содержит исходный демонстрационный
контент, `scripts/seed.mjs` создаёт его через HTTP API без прямой записи в БД.
Рабочий frontend не читает `content.mjs`: источником контента служит CMS.

Это локальное демо. Оно не развёртывает сайт в интернете и не настраивает TLS.

## Проверки

Проверка серверного вывода, кодов ответа, изоляции management API и поиска:

```bash
docker compose --profile demo run --rm --no-deps demo node --test
```

При подготовке демо дополнительно проверены в Chromium все 12 страниц на ширинах
1440 и 390 px, 13 внутренних адресов, переходы по карточкам, поиск с результатами
и без результатов, раскрытие FAQ, 404 и отсутствие ошибок страницы/консоли.
Проверено сохранение контента через редактор админки и появление изменений
на публичной странице без пересборки; тестовое изменение отменено.
