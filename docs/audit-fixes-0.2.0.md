# Исправления аудита — 0.2.0

23 сентября 2026. Starter, ядро и независимая админка.

| Замечание | Исправление |
| --- | --- |
| Известный dev-администратор при обычном запуске | Dev-seed требует `CMS_DEV_SEED=true`; `bootstrap-admin` создаёт администратора через доменный сервис и не перезаписывает существующего. `make env` генерирует секреты. |
| Неограниченная стоимость входа | До Argon2 применяются лимиты 30/IP/минуту и 10/(IP, логин)/минуту; одновременно работают максимум две проверки на экземпляр сервера. Перегрузка возвращает 429/503. |
| Поздняя запись устаревшего кэша | Зависимости захватываются до чтения источника. Инвалидация во время загрузки делает позднюю запись недействительной. |
| Устаревшая публичность сайта на другой реплике | Запрос сверяет версию runtime с PostgreSQL. Несовпадение возвращает 503; фоновая синхронизация обновляет снимок. Обновления сайта проверяют ожидаемую версию. |
| События отбрасывались | Starter использует Kafka, подтверждение публикации учитывается outbox. Compose включает брокер и постоянный volume. |
| Starter использовал старое ядро | Зависимость закреплена на опубликованном `go-cms-kernel v0.2.0`, без `replace` и `go.work`. |
| Нет публичного подключения/замены расширений админки | `createAdminApp`/`mountAdmin` принимают `plugins`, `overrides`, `history`; роутер и registry создаются для каждого приложения. Случайные дубликаты запрещены. |
| Одновременные холодные загрузки и обработка изображений | Загрузки одного ключа координируются; попадания в кэш не сериализуются. Миниатюры объединяют одинаковые вычисления, общий лимит обработки изображений — две операции. |
| Неограниченный рост Redis generations | Максимум 65 536 слотов поколений на физическое хранилище; коллизия приводит только к дополнительной инвалидации. Отсутствующее поколение означает промах. Redis ограничен 256 MiB. |
| JWT не отзывались | Сессии сохраняются в PostgreSQL. Logout отзывает текущий токен; смена пароля — все. Одновременный вход со старым паролем не выдаёт действующую сессию. |
| Уязвимая версия x/image | Обновлена до v0.43.0; whitelist форматов и ограничения изображений сохранены. |

## Проверки

- Starter: `GOWORK=off`, публичные Go proxy/sumdb, test/vet/build и Compose config. `make test-deployment` прошёл на свежих volumes: API, ресурсы, public/private файлы, запреты доступа, видимость ошибки запуска и сохранность после пересоздания контейнеров.
- Ядро: `go test ./...`, `go vet ./...`, `go build ./...`, `go mod tidy -diff`.
- Race detector: кэш, Redis/filesystem connectors, core, app, изображения, JWT, HTTP authentication.
- PostgreSQL: интеграционные тесты core, отзыв сессий, конфликт со сменой пароля.
- PostgreSQL + Redis: жизненный цикл кэша и синхронизация двух экземпляров App на отдельной чистой БД.
- Kafka: публикация, получение и повтор обработки на реальном брокере; реальный starter получил подтверждение публикации outbox.
- HTTP: обычный запуск отвергает известный dev-пароль; bootstrap создаёт аккаунт и отвергает перезапись; logout сохраняет вторую сессию; смена пароля отзывает все старые сессии.
- Админка из чистой копии с `npm ci`: 55 файлов / 217 тестов, проверка Vite env, typecheck, сборка приложения и SDK, `npm pack`; отдельный Vite/TypeScript host установил архив и собрал собственный plugin/override. `npm audit`: 0.
- `govulncheck`: 0 уязвимостей в вызываемых символах ядра и starter. В графе зависимостей остаются предупреждения без найденных вызовов: ядро — 1 на уровне импортированных пакетов и 6 на уровне модулей; starter — 1 и 5 соответственно.

Ограничения: это регрессионные и конкурентные проверки, не измерение максимального RPS или длительный нагрузочный прогон. Kafka в стандартном Compose имеет один брокер. Лимиты входа действуют на экземпляр; за reverse proxy учитывается его RemoteAddr, forwarded-заголовки не считаются доверенными автоматически. Интеграция с S3 не запускалась.

## Обновление

Исправлены исходные pre-production миграции. Для прежней dev-БД требуется пересоздание; совместимость со старой схемой не предусмотрена. Старые JWT не являются зарегистрированными сессиями. Обновляйте backend и admin вместе. Пользовательские базы и volumes в ходе работы не сбрасывались: проверки использовали отдельные тестовые окружения.
